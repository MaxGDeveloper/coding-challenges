## Тестовое задание: Веб-приложение «Прогноз погоды»

**Ориентировочное время:** 1–2 дня (8–16 часов)

---

### Стек

- **Vue 3.5+** (Composition API, `<script setup>`, TypeScript, strict mode)
- **Vite** — сборщик
- **vue-router 4.4+** — маршрутизация
- **PrimeVue 4.5.5** — UI-компоненты (документация: https://v4.primevue.org/vite)
- **Open-Meteo API** — данные погоды (бесплатно, без ключа: https://open-meteo.com)

**Создание vue 3 приложения**: https://ru.vuejs.org/guide/quick-start.html

В качестве бесплатного апи можно рассмотреть например [OpenMeteo](https://open-meteo.com/en/docs) или любой другой бесплатный сервис.

---

### Описание

Небольшое приложение из двух страниц. Пользователь выбирает город — приложение показывает текущую погоду и почасовой прогноз на ближайшие сутки.

### Страница 1 — Главная (`/`)

Приветственный текст (2–3 строки) и форма выбора города.

UI-элементы:

- **Текстовое поле** для ручного ввода названия города.
- **Кнопка «Определить автоматически»** — использует бесплатное апи (на твой выбор) для получения названия города по координатам. Определённый город подставляется в текстовое поле.
- **Кнопка «Перейти к погоде»** — активна только когда поле ввода не пустое.

По нажатию на «Перейти к погоде»:

1. Город сохраняется в `localStorage` (ключ `lastCity`).
2. Происходит переход на `/weather/:city`, где `:city` — введённое значение.

Дополнительно: при загрузке главной страницы, если в `localStorage` есть сохранённый город, подставить его в поле ввода как значение по умолчанию.

> Если вы выбираете альтернативный сервис геокодинга (не Nominatim), обязательно разместите ссылку на его документацию на главной странице (например, в подвале или в виде сноски).

### Страница 2 — Погода (`/weather/:city`)

Данные запрашиваются из API:

- **Текущая погода**: температура, ощущается как, влажность, скорость ветра, погодное описание (в общем то, что будет доступно в АПИ).
- **Почасовой прогноз на ближайшие 24 часа**: температура и погодный код. Визуально — таблица или карточки по часам.

UI-элементы:

- Название города (из параметра маршрута).
- Блок текущей погоды.
- Блок почасового прогноза.
- **Кнопка «Назад»** — возврат на главную.

Дополнительно: при прямом заходе на `/weather/:city` (без перехода с главной) приложение должно корректно работать — данные запрашиваются по городу из URL.

---

### Обработка ошибок

- **Невалидный город** (геокодинг не смог определить координаты или погодный API вернул пустой результат для указанного города): показать сообщение пользователю, предложить вернуться и попробовать другой город.
- **Отказ в геолокации** (пользователь не дал доступ или API недоступен): показать всплывающее сообщение, оставить поле ввода доступным для ручного ввода.
- **Ошибка API** (сеть недоступна, 5xx): показать сообщение об ошибке с кнопкой «Повторить запрос».

---

### Требования к коду

- TypeScript в режиме `strict: true`.
- Разумная структура: компоненты, composables, типы, API-сервисы — в отдельных файлах, не всё в одном компоненте. Желательно выделить:

    - composables/useWeather.ts — логика запросов к погодному API.

    - composables/useGeocoding.ts — логика автоопределения города.

    - services/weatherApi.ts — вызовы Open-Meteo.

    - services/geocodingApi.ts — вызовы геокодинга.

    - types/ — интерфейсы для погоды, геокодинга.

- ESLint + Prettier (минимальная конфигурация, без warnings в итоговом коде).

---

### Критерии приёмки

1. `npm install && npm run dev` запускается без ошибок.
2. Минимальная адаптивность сайта к небольшим экранам.
3. Ручной ввод города → переход на страницу погоды → отображаются текущая погода и почасовой прогноз.
4. Автоопределение города → город подставляется в поле → переход и отображение работают аналогично.
5. Обработка ошибок: невалидный город, отказ геолокации, ошибка API — каждый сценарий показывает понятное сообщение.
6. Сохранённый в `localStorage` город подставляется в поле при повторном заходе на главную.
7. Почасовой прогноз отображает данные за ближайшие 24 часа от текущего момента (или с начала текущего часа).

---

### Что оценивается

- Структура и читаемость кода, разделение ответственности.
- Корректная работа с TypeScript (типы, интерфейсы, отсутствие `any`).
- Использование Composition API и `<script setup>`.
- Качество работы с API (обработка loading/error-состояний).
- Адекватное использование компонентов PrimeVue.

> Примечание про запасной вариант: Если по каким-то причинам использование Open-Meteo или геокодинга невозможно, допускается реализовать сервис-заглушку, генерирующую случайные, но правдоподобные данные (температура, влажность и т.д.). В этом случае в коде должен быть комментарий, объясняющий, что это заглушка. Однако приоритет — работа с реальными API.
