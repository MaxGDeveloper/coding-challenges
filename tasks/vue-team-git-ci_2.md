# Командный сайт на Vue 3 + Git + GitHub Actions + GitHub Pages

**Формат:** групповая работа в одном публичном репозитории.  
**Стек:** Vue 3, Composition API, `<script setup>`, Vite, TypeScript, Vue Router.  
**Цель:** сделать общий сайт и освоить работу с ветками, Pull Request и CI/CD.

## 1. Что должно получиться

Публичный сайт на GitHub Pages:

- `/` — главная страница со списком карточек разработчиков.
- `/<name>` — личная страница студента. Для каждого студента свой путь.

Карточка — **один общий компонент** `DeveloperCard`. Техлид пишет его один раз, студенты не меняют, а только передают свои данные. Карточка ведёт на личную страницу автора.

## 2. Роли

| Роль | Что делает |
|---|---|
| **Техлид** | Создаёт репозиторий и каркас проекта, общий компонент, главную, пример личной страницы, настраивает CI/CD и GitHub Pages, защищает `main`, проводит демо. Свою карточку и страницу добавляет так же, как все. |
| **Студент** | Создаёт ветку, добавляет карточку на главную и свою личную страницу, открывает Pull Request в `main`, проходит CI, мержит и проверяет деплой. |
| **Преподаватель** | Принимает работу и проверяет понимание механизма. |

## 3. Этап 1. Каркас и инфраструктура

1. Создать пустой публичный репозиторий по инструкции [Github Pages](https://docs.github.com/ru/pages/getting-started-with-github-pages/creating-a-github-pages-site).
2. Создать проект Vue 3 + Vite + TypeScript + Vue Router. Установить зависимости, сделать первый commit и push в `main`. `package-lock.json` должен быть закоммичен.
3. Сделать общий компонент `DeveloperCard`:
   - props: `name`, `role`, `shortDescription`, `to`; `avatar` — необязателен;
   - показывает аватар или инициалы, имя, роль, краткое описание и «Подробнее»;
   - вся карточка — ссылка на `to`, без вложенных ссылок и кнопок;
   - стили `scoped`.
4. Сделать главную `/`: заголовок, адаптивная сетка карточек, одна карточка-пример техлида.
5. Сделать пример личной страницы и маршрут `/<name>` для техлида. На странице должны быть блоки: шапка, «Обо мне», «Навыки и проекты», «Контакты / увлечения».
6. Удалить демо-компоненты и лишние демо-стили шаблона.
7. В конфиге Vite настроить корректный `base` для GitHub Pages.
8. Настроить CI: на Pull Request в `main` выполняются `npm ci` и `npm run build`. Job называется `build`.
9. Настроить CD: на push в `main` выполняется сборка и деплой папки `dist` на GitHub Pages.
10. Включить Pages: Source — GitHub Actions. После первого успешного деплоя защитить `main`: обязательный Pull Request, 1 approval, обязательная проверка `build`, запрет force push и удаления ветки.
11. В README указать URL сайта, локальный запуск, правило веток и Pull Request, техлида. Провести короткое демо группе.

## 4. Этап 2. Добавить себя (каждый студент делает индивидуально)

1. Склонировать репозиторий, выполнить `npm i`, проверить локальный запуск.
2. Забрать все изменения из ветки `main` и создать ветку `feature/<имя-фамилия>`.
3. На главной странице **в конец списка** добавить свою карточку через `DeveloperCard`: имя, роль, краткое описание, `to="/<name>"`. Фото можно передать через `avatar`, если его нет — компонент покажет инициалы.
4. Создать свою личную страницу `/<name>` с блоками: шапка, «Обо мне», «Навыки и проекты», «Контакты / увлечения».
5. В конец массива маршрутов добавить маршрут `/<name>`, имя маршрута `<name>`, компонент — своя страница.
6. Локально выполнить `npm run build`. Сделать осмысленные коммиты. Не коммитить `node_modules`, `dist`, `.env`.
7. Запушить ветку и открыть **Pull Request в `main`**. В описании указать: что добавлено, ожидаемый URL страницы, скриншоты, чек-лист.
8. Дождаться зелёного CI. При конфликтах сохранить все карточки и все маршруты, включая чужие.
9. После approval и зелёного CI сделать merge, удалить ветку, дождаться деплоя и проверить свою карточку и страницу на сайте.

Компонент `DeveloperCard` студентам менять нельзя. Если есть проблема — написать техлиду.

## 5. Как изменение попадает на сайт

```
ветка студента → Pull Request → review/approval → зелёный CI → merge в main → deploy → GitHub Pages
```

Push в ветку деплой не запускает. Сайт обновляется только после merge в `main`.

## 6. Правила Git

- Один студент — одна ветка — один Pull Request.
- Ветка: `feature/<имя-фамилия>`.
- Коммиты осмысленные.
- Pull Request только в `main`, после зелёного CI и approval.
- Merge — squash, ветку удалить.
- При конфликтах не удалять чужие карточки и маршруты.
- Не коммитить `node_modules`, `dist`, `.env`, секреты и большие файлы.
- Никакого force push в `main`.

## 7. Что сдать

- ссылку на Pull Request;
- ссылку на зелёный CI;
- ссылку на личную страницу `https://.../<name>`;
- ссылку на успешный deploy run.

## 8. Критерии приёмки

- [ ] Сайт открывается по публичному URL.
- [ ] На главной видны карточки всех студентов.
- [ ] Каждая карточка ведёт на личную страницу автора.
- [ ] На личной странице есть 3+ обязательных блока.
- [ ] Используется общий компонент `DeveloperCard`, студенты его не переписывали.
- [ ] `main` защищён: прямой push невозможен.
- [ ] Все изменения прошли через Pull Request и review.
- [ ] CI на Pull Request зелёный, deploy на `main` зелёный.
- [ ] После merge сайт обновился.
- [ ] В репозитории нет секретов, `node_modules` и `dist`.
